# Инструкция по настройке автоматического деплоя

---

## 1. Добавить публичный ключ на сервер

GitHub Actions подключается к серверу по SSH. Сервер должен принимать твой личный ключ.

**На своём ПК** (в PowerShell или Git Bash) посмотри публичный ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируй вывод (одна строка вида `ssh-ed25519 AAAA... krogan98@mail.ru`).

**На сервере** (через PuTTY) добавь его в authorized_keys:

```bash
# Вставь скопированную строку в кавычки и выполни (или отредактируй ~/.ssh/authorized_keys вручную)
echo "ВСТАВЬ_СЮДА_СОДЕРЖИМОЕ_id_ed25519.pub" >> ~/.ssh/authorized_keys
```

Если этим ключом ты уже заходишь на сервер по SSH, этот шаг можно пропустить — ключ уже есть в `authorized_keys`.

---

## 2. Права для перезапуска nginx

Нужно, чтобы пользователь мог перезапускать nginx без ввода пароля:

```bash
sudo visudo
```

Добавь строку (подставь свой username):

```
username ALL=(ALL) NOPASSWD: /bin/systemctl restart nginx
```

---

## 3. GitHub Secrets

В GitHub Actions будет использоваться **приватная** часть твоего личного ключа. Её нужно один раз положить в секреты репозитория.

**На ПК** открой приватный ключ и скопируй целиком (включая строки `-----BEGIN...` и `-----END...`):

- Windows (PowerShell): `Get-Content $env:USERPROFILE\.ssh\id_ed25519 -Raw`
- Или открой файл в блокноте: `C:\Users\sereg\.ssh\id_ed25519`

**В GitHub:**

1. Репозиторий → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret**, создай три секрета:

| Name            | Value |
|-----------------|--------|
| `SERVER_HOST`   | IP или домен сервера |
| `SERVER_USER`   | Твой логин на сервере (как в PuTTY) |
| `SSH_PRIVATE_KEY` | Весь скопированный приватный ключ `id_ed25519` |

**Важно:** в `SSH_PRIVATE_KEY` вставляется именно личный ключ (`id_ed25519`), не рабочий и не публичный.

---

## 4. Проверка

1. Сделай коммит и пуш в `main` или `master`
2. В репозитории открой вкладку **Actions**
3. Должен запуститься workflow **Build and Deploy**
4. Открой запуск и посмотри логи — зелёная галочка = деплой прошёл успешно

**Ручной запуск:** **Actions** → **Build and Deploy** → **Run workflow** → **Run workflow**

---

## Что делает workflow

1. Клонирует код, при необходимости ставит зависимости и собирает проект
2. Копирует содержимое `dist/` на сервер в `/var/www/holoxdubai/`
3. Выполняет `systemctl restart nginx` на сервере
4. Статус и логи видны в GitHub Actions

---

## Безопасность

- Один и тот же ключ используется для доступа к GitHub с ПК и для деплоя (доступ к серверу из Actions).
- Приватный ключ хранится только на твоём ПК и в GitHub Secrets (доступ только у этого репозитория и его workflow).
- Для других репозиториев можно завести отдельный ключ и повторить шаги с ним.

## Troubleshooting

**Permission denied (publickey)**  
- На сервере проверь: `cat ~/.ssh/authorized_keys` — там должна быть строка из `id_ed25519.pub`.  
- В Secrets должен быть именно приватный ключ (`id_ed25519`), не публичный.

**sudo: no tty present**  
- Настрой NOPASSWD для `systemctl restart nginx` (шаг 2).

**Ошибка при копировании в /var/www/holoxdubai/**  
- Права на каталог: `sudo chown -R $USER:$USER /var/www/holoxdubai/`  
- Или убедись, что `SERVER_USER` — тот пользователь, которому разрешён доступ к этому каталогу.
